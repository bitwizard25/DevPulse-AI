# DevPulse MVP implementation plan

Goal: ship a terminal code reviewer with durable local state, bounded project context, secret redaction, and a shared local gateway.

Architecture: Python 3.11+ standard-library package. One loopback HTTP gateway owns a serialized review engine, SQLite WAL state and exact response cache. CLI can also review directly. Project Markdown is explicit persistent memory; raw prompts and credentials are never stored in the database.

The user authorized direct implementation and delegated MVP choices. MCP, GitHub writes, vector cache, automatic edits and hardware performance predictions are deferred. No guarantee of bug-free output or complete secret detection.

## Tasks

- [x] State and privacy: request-local redaction, redacted storage, TTL cache, interrupted session recovery and keyed identities. Domain privacy plus infrastructure state adapters.
- [x] Context and source intake: byte budgets, path containment, memory invalidation and safe Git argument handling. Infrastructure adapters.
- [x] Review engine: queued duplicate reuse, exact cache, provider failover, invalid response rejection and Python checks. Application service/router and pure domain checks.
- [x] Product surface: CLI subprocesses, gateway authentication/ownership/lifecycle, bounded requests and errors. Focused interface handlers, packaging and README.
- [x] Verify: 30 unittest tests pass on Windows/Python 3.14.7; includes actual temporary Git snapshots and CLI daemon lifecycle. Wheel and source distribution built. Installed-wheel smoke outside checkout passes CLI, memory, redaction, syntax findings, history and gateway start/status/stop. `git diff --check` passes. Native live provider inference remains unverified; provider protocols use real local HTTP fixtures. Git emits a sandbox warning about the inaccessible global ignore file, without failing checks.

## Boundaries

- Cloud calls only receive redacted source plus bounded redacted context. Findings remain redacted; no automatic secret restoration.
- Exact cache identities include project, source, rules, memory, skills, provider configuration and prompt schema. Original input only contributes keyed HMAC digests to identity.
- Persistent sessions use running/completed/failed/interrupted states; metadata only. Restart recovery belongs only to the exclusive gateway owner, never a random client.
- Provider output is untrusted data and is strictly validated. No model-generated command is executed and no proposed patch is applied.
- Environment keys are read at request time, never written to config. HTTP is allowed only for loopback endpoints; remote inference requires HTTPS.
- Offline deterministic checks work without an LLM; clearly distinguish them from model review.
- Default source is staged Git diff, with explicit worktree diff and whole-file options. Memory is explicitly edited, never automatically inferred from code.

## Review focus

Malformed and oversized HTTP/provider data; cross-project cache reuse; new secrets colliding after redaction; concurrent SQLite writes and duplicate requests; missing Ollama and unset cloud keys.

## User-directed architecture revision

The user explicitly requested clean architecture during implementation. Final layout separates `domain`, `application`, `infrastructure`, and `interfaces`. Application Protocol ports are injected at `bootstrap.py`; neither inner layer imports concrete adapters. CLI parsing, command handlers and rendering have separate responsibilities. An architecture test enforces inward dependency direction. See `docs/architecture.md`.
